# API 降本实施方案与验收

## 目标与边界

先消除无效调用，再降低辅助环节单价。正文质量、用户选择的型号、疑问句独立盲测、真实联网和证据审计不降级。
不缓存旧回答冒充新检测，不减少检测问题或模型数量，不删除欠费账号，不修改用户积分定价。
上游已执行但未返回 usage 的请求可能收费，不能按零成本统计。

## 已核查的主要问题

1. 全局豆包型号由 Lite 切到 Pro 后，正文与质量裁判同时使用昂贵型号。
2. 文章先做语义审查，再修复本地就能识别的问题，修复后又审一次。
3. 裁判没有结果时可能被当作质量通过；修复失败可能丢失本次已有正文。
4. API 池无可用账号时可能回退旧 Key 或放弃型号约束。
5. AccountOverdueError 的 HTTP 403 被当成权限错误，未进入账号级欠费隔离。
6. 自动探测可能重开已恢复的线路，且成功探测会重排默认型号。
7. 消耗日志偏重文章生成，取消、超时以及豆包 Responses 联网用量存在缺口。

## 实施顺序

### 1. 账号与请求保护

- 识别 AccountOverdueError / overdue balance 为欠费，不再作为单项能力权限问题处理。
- 保留 enabled 状态和 Key；失败账号暂时隔离，其他合格独立账号继续接单。
- 每条失败线路按冷却时间低频复查。欠费默认一小时；批量探测限额可能延后实际恢复时间。
- 尊重账号冷却时间，不重开已有健康线路；自动探测不更改型号排序。
- 保留管理员手动复检，不要求用户重新录入 Key。
- 已配置账号池的模块不得绕过池回退旧 Key；指定型号不存在或全冷却时明确失败，不静默改型号。
- 无合格账号及时返回；有健康账号但并发满时仍排队。
- 真实阶段超时计入线路故障，主动取消不计入健康故障。

### 2. 文章分工

- 正文、改写、内容修复仍使用用户选定型号及原有 Prompt、资料。
- 质量裁判和创作类型分配使用独立辅助型号，默认 qwen-plus 非思考模式。
- 配置为 ARTICLE_AUXILIARY_MODEL_PROVIDER=qwen、ARTICLE_AUXILIARY_MODEL=qwen-plus；仅服务器配置，不接受前端绕过。
- 辅助模型不可用不偷偷换成昂贵正文模型；保留原稿待复核，类型分配保留已有规则回退。
- 不为本次降本额外打开 AI 写作规划器。

### 3. 减少返工

正常：生成 → 本地检查 → 一次语义审查。
本地不合格：生成 → 本地检查 → 至多一次修复 → 本地检查 → 合格后语义审查。
语义不合格：生成 → 本地检查 → 语义审查 → 至多一次修复 → 再检查审查。
裁判异常不触发整篇重写，不标为优质；修复异常保留原稿，可人工审阅和下载。
修复后的文章必须取得自己的新裁定，不沿用修复前的通过结果。
文章 HTTP 层临时错误重试从三次降为一次；质检不做同账号 HTTP 重试，由现有账号池切换。
保留有依据的批次相似度检查，暂不改变去同质化规则。

### 4. 消耗留痕

- 增加账号 ID、usage 是否返回、缓存输入及思考输出的可选计数。
- 记录文章中断与失败；通用池调用与主适配器按模块记录。
- 豆包 Responses 在答案与信源验收之前提取 usage，验收不通过仍保留已知消耗。
- 没有调用方用户信息的记录明确标为 unattributed，不伪造归属。
- 历史记录不倒填零消耗；思考 Token 是输出的组成部分，缓存 Token 是输入的组成部分，不能重复相加。
- scripts/report-ai-usage.mts 按北京时间、模块、型号和账号只读汇总最近 1~90 天。
- 不是厂商账单替代品：独立搜索工具费、部分旧直连与外部搜索多轮路径仍需账单对账。

## 价格与效果判断

按公开标准价举例，10,000 输入 + 1,000 输出 Token：
- 豆包 Seed 2.1 Pro，输入 6 / 输出 30 元每百万，约 0.09 元。
- qwen-plus 北京非思考档，输入 0.8 / 输出 2 元每百万，约 0.01 元。

## 后续降本门槛

不能仅因便宜把正文全部切换 Lite。使用同一题目、同一优势、同一资料和模板进行小样对照，
比较事实错误、可发布率、修复率、每篇合格文章的总费用和人工复核负担。
通过后才调整文章专用默认值，不修改渗透率检测默认型号；用户显式选择继续优先。
待有明确日预算再使用已有账号预算控制，不随意设置会中断正常业务的额度。
费用对比必须按同一模块、同一任务量和同一日志覆盖范围，不能把新增日志当成新增消费。

## 验收

- 欠费后无旧 Key 旁路、无昂贵型号替换；充值后自动与手动恢复。
- 本地检查不合格时不提前质检；裁判失效不误判通过；修复失败保留正文。
- 写作型号不被裁判型号覆盖；未知用量与确认用量区分。
- 单篇、批量、自动成文、Agent、联网盲测、并发排队回归测试。
- TypeScript、定向 ESLint 和生产构建通过后发布；不打断正在运行的付费任务。

## 第二轮执行与实测（2026-09-07）

### 阶段一：减少结构冲突与误判返工

只读检查最近 7 天批量稿的质量记录，发现旧通用五段提纲与白皮书、案例、评测的形态存在冲突。
同时发现裁判将输入已有事实、一般核验建议误判为缺少第三方依据；裁判此前只看到形态名称，
未拿到生成端完整的形态规则，可能要求生成端补上该形态本来允许省略的材料。

- 默认提纲直接使用现有文章形态的 answerPattern，不再另造一套结构。
- 裁判同步获得同一份形态结构、表格策略和资料不足处理规则。
- 区分用户资料、主体自述、独立认证、编辑建议和新增事实断言。
- 未给报价不能推出更便宜；内部资料不能冒充公开检索；未填写不能解释为不存在。
- 保留 80 分、无阻断问题、本地检查通过的合格条件，不把失败或未完成判断当成通过。
- 裁判优先报告主要问题，合并同一根因，不输出冗长重复点评；没有增加常规调用次数。
- 内容流水线版本更新为 shitu-article-2026.09.1，既有文章与历史审计不重写。

### 阶段二：稳定可复用前缀

原时间注入在请求第一行，精确到秒，打断稳定 Prompt 前缀。
文章 OpenAI-compatible 调用改为在用户输入之后附当前时间，模板、资料、文章内容均保留。
其他模块仍使用原时间位置；rawQuestionOnly 仍不注入任何时间或业务指令。
原生 Anthropic/Gemini/Responses 路径本来没有该时间注入，本轮不改其请求。

这是方便上游复用输入计算，不是保存旧答案，不共享不同账号的结果。
不创建付费显式缓存，不更换接口，不增加账号黏性或影响并发分配。
百炼隐式缓存要求足够长的相同前缀，命中不保证；不同账号、型号缓存隔离。
本轮样本未观察到已计量的缓存命中，不承诺已节省相应费用。
依据：https://help.aliyun.com/zh/model-studio/context-cache

### 阶段三：正文降档与关闭思考的质量门槛

两份内部合成资料，经真实文章接口捕获完整 Prompt 后，固定输入分别测试 Pro、Lite、Lite 关闭思考。
没有客户资料出站，没有创建客户报告或扣用户积分。共 6 次正文测试、8 次裁判/对照校验；
有 1 次 Pro 请求到测试的 120 秒上限未返回 usage，不能按免费计算，也不能据此断言生产 180 秒请求必失败。

同一对比题的返回用量：

| 模式 | 输入 Token | 输出 Token | 其中思考 Token | 单次正文耗时 |
| --- | ---: | ---: | ---: | ---: |
| Seed 2.1 Pro | 5660 | 6235 | 4857 | 119.3 秒 |
| Seed 2.0 Lite | 5663 | 3481 | 2455 | 86.8 秒 |
| Seed 2.0 Lite 关闭思考 | 5659 | 1639 | 0 | 36.2 秒 |

Pro 此样本约 78% 的输出为思考 Token；Lite 两个默认思考样本均约 70%。
关闭思考有显著降耗潜力，但另一篇关闭思考的指南违反表格规则、漏了已填的两个对比主体。
部分稿件虽然获得裁判高分，人工阅读仍发现无依据的价格比较和来源公开性断言。
修正裁判规则后，独立校验中：人工准备的有依据正例通过（92 分），上述问题稿不通过（62 分）。
这只验证针对性样本，不代表裁判完全可靠或某型号适用于所有行业。

结论：本轮不强制切换正文默认型号、不关闭生产正文思考，也不替换用户明确指定的型号。
先上线已验证的结构、审核一致性和稳定前缀改动。模型降档继续保留质量门槛，不能把单次报价
或单个 AI 分数等同于每篇合格文章成本；需覆盖真实模板、证据强弱与最终修复成本后再扩大使用。
