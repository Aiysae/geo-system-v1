# Agent / CLI 文章类型参数修复

## 线上证据

2026-09-23 核查：Agent API 开关开启，准入模式为 all；公开入口、CLI 下载和接入指南正常。下载脚本与仓库 CLI 一致。未携带 Token 的受保护接口返回预期的 401。

最近 7 天审计包含 article.generate 的 1291 条 HTTP 500 记录，也有文章提交成功及查询类动作成功记录。这是接口请求数，不是付费模型调用数或失败文章数。服务错误日志持续出现“请选择有效的文章 Prompt”，部分请求约每三分钟重复。

根因：Agent 输入规范把 promptKey 定义为任意非空字符串；无效值通过入口后，在费用估算阶段触发普通异常，又被包装为可重试的 INTERNAL_ERROR / HTTP 500。调用方因此看不到真正的参数错误。未取得反馈者的完整请求，尚未确认其具体错误值。

## 修复

复用 ARTICLE_PROMPT_PRICE_KEYS 的 13 个有效标识作为共享枚举，应用于单篇文章、批次基础配置和批次问题条目。Agent capabilities、OpenAPI、MCP 工具参数说明从同一规范生成，因此同时提供有效选项。

无效 promptKey 在入口返回 INVALID_ARGUMENT / HTTP 400 / retryable=false，并指出字段及有效值。保留显式选择，不猜测或静默替换用户的文章类型。

## 验证

Agent API、CLI、MCP、63 个动作的功能覆盖检查通过；改动文件 ESLint 与 git diff --check 通过。接口覆盖测试使用隔离数据，不等于全部线上付费功能逐项生成成功。

接入方应重新读取 capabilities 或重新连接 MCP。旧脚本若硬编码无效类型，需要根据 articles settings 返回的类型改正；重试原错误参数仍会被拒绝。此故障与豆包 Turbo 账号允许列表遗漏为独立问题。
