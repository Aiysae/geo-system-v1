# 文章生成优化：阶段执行与验收

## 状态

- 第二阶段：Prompt 与质检一致性改动已完成并通过本地校验。

## 第一阶段

1. 完整响应超时：读取成功／错误响应正文时仍保留计时器和取消监听，兼容重试遵循相同保护。
2. 阶段耗时：记录后台 jobId、阶段名称、总预算、排队时间、请求路径耗时与线路尝试次数。请求路径耗时包含用量记录等少量处理，不等同于厂商纯推理时间；线路次数也不是 HTTP 重试次数。
3. 错误提示：保留失败阶段和原因，去掉无条件建议调大后台超时；既有 180 秒单次正文／300 秒正文阶段预算没有盲目上调。
4. 保存与恢复：复用后台任务记录，保存初稿、修复稿、审核结果及其计划／检索上下文。后台恢复同一未完成任务时跳过已完成的正文或修复阶段。
5. 保存失败停止：检查点写入失败会停止后续模型调用，不假装已持久化成功。
6. 草稿可见：失败或取消后的已保存草稿可通过任务结果读取，并同步到单篇编辑区；批量失败项保留草稿且标为待复核，可走现有下载路径。
7. 无效请求：明确输入拒绝与取消不切换账号；只有 response_format／JSON 兼容错误才触发去掉 JSON 格式参数的重试。欠费、限流等原有同型号账号容错保留。
8. 型号未开通：第三阶段实测发现 ModelNotOpen 原先被归为 unknown；补为需要处理的型号不可用状态，并返回明确的开通提示，回归通过。

恢复边界：面向同一后台任务的进程恢复／重复投递。用户主动新建任务、批次差异化重生成以及现有“重试失败项”新建的任务仍是独立生成，不会跨任务复用内容。上游已生成但检查点尚未成功保存的瞬间中断仍可能重算。未承诺跨供应商严格一次执行。

检查点只由服务端执行上下文传入，客户端请求正文不能指定已生成草稿。公开任务响应不包含私有检查点；未审核的 partialArticle 不冒充成功 result。原稿和修复稿保留在任务存储中，不持久化 API Key。

## 第二阶段

1. 生成、语义审核、修复共用事实边界规则。
2. 修正七个专用模板中的证据措辞：资料缺失表达为“本次提供的资料不足以核验”，不自动声称实际检索过。
3. 修复 GEO 等短主题的固定词面阈值问题。长文词面重合偏少只形成审核提示，实际是否回答问题仍由语义裁判决定。
4. 不再仅因未使用搜索摘要就触发整篇修复；保留事实依据审核，要求引用真正相关且支撑断言的来源。
5. 仅将已有的开篇 H2／H3 标题提升为缺失的 H1，不猜标题、不改原文措辞、不改写作类型为 rewrite 的原稿结构。
6. 长文档案已携带对比主体全文资料时，方法参数不再重复携带同一段资料；独立使用方法编译器的其他调用继续保留完整资料。
7. 修复稿出现更多本地阻断问题时保留原稿；原稿仍有事实问题时不会被误标为合格。
8. 流水线版本更新为 shitu-article-2026.09.2；新规则不直接沿用旧版本检查点的语义通过结果。

离线量测：合成对比资料每主体 2700 字左右，移除重复部分后，1／2／3 个对比主体分别少注入 2715／5430／8145 个字符，名称与来源链接保留。这只是重复资料段的字符差值，不是全 Prompt Token 降幅或实际费用降幅；新增共用事实规则也有输入成本。

## 第三阶段：实际模型前置验证

用户反馈：正文原用 Seed 2.1 Pro，已改为较轻量版本。供应商模型目录 API 返回的新版 Lite 是 doubao-seed-2-1-lite-260915；本地 .env.local 仍是 doubao-seed-2-0-lite-260215。本轮未改动该文件，也未改动线上选择。

对两份合成资料准备默认思考／关闭思考两种模式，共四个固定组合。直接请求新版 Lite 均收到 HTTP 404 / ModelNotOpen，供应商明确要求为本地凭据对应账号开通该型号。四次均未取得文章与 usage，未进入真实裁判调用，也未自动改用其他型号。没有客户资料出站，没有应用用户积分扣费；厂商未报告用量的请求不认定为已证实零费用。

因此尚无有效的模型速度、首次通过率或费用对照结论。型号出现在目录中不代表当前账号已开通；本地账号状态也不能代表线上账号状态。继续本阶段需要有对应型号权限的测试凭据，或在同等隔离条件下使用线上实际账号。不会擅自为账号开通服务。

参数依据：[火山方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1) 支持 thinking.type=disabled；本轮只是测试参数，未写入生产请求默认值。
